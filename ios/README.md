# iPhone app

The iPhone version of KU WBB, built by GitHub Actions and delivered through
TestFlight.

It is a thin shell around the shared Kotlin code in `shared/`: the same
screens, database, season sync and Ask as the Android app, drawn with Compose
Multiplatform. The Swift here only puts those screens on the phone — 28 lines
of it, and no AppDelegate, because this app sends no push alerts.

- `project.yml` describes the Xcode project for XcodeGen; CI generates the
  `.xcodeproj` from it, so that file is never committed or hand-edited. Its
  build step runs Gradle to compile `shared/` into `Shared.framework` for the
  device or simulator being built.
- `App/` holds the Swift entry point and the icon. The season data the app
  starts from (`app/src/main/assets/seed.json`) is bundled too, as a resource
  rather than compiled in, because `Seeder` reads it from the bundle by name.
- `App/Assets.xcassets/AppIcon.appiconset/icon-1024.png` is generated by
  `scripts/make-web-icons.mjs`, from the same artwork as the Android launcher
  icon and the dashboard's. It is the one icon that must carry no alpha
  channel at all — App Store Connect rejects one that does — so the script
  strips it, and refuses if the art ever gains a transparent pixel.
- `check_apple_keys.py` (run by the "Apple keys check" workflow) confirms the
  four Apple secrets work without printing them.

## Workflows

| Workflow | Runs on | What it answers |
|---|---|---|
| Apple keys check | Linux, ~30s | Are the four secrets right? |
| iPhone shared code | Mac, ~15m | Does the shared code compile and pass its tests for iPhone? |
| iOS TestFlight build | Mac, ~40m | Can it be signed, uploaded and installed? |

They are in that order on purpose: each is cheaper than the one after it and
rules out a different thing, so a failure in the last one is about signing
and packaging rather than about the code or the credentials.

"iOS TestFlight build" runs when anything here changes on a branch, or by
hand from the Actions tab. Each upload takes the workflow's run number as its
build number, and Apple then spends 5–30 minutes processing it before it
appears in the TestFlight app.

## Secrets

Set in the repository's Settings > Secrets and variables > Actions:
`APPLE_TEAM_ID`, `ASC_ISSUER_ID`, `ASC_KEY_ID`, `ASC_KEY_P8` — the App Store
Connect key that signs and uploads builds. It must be an **Admin** key: a
lower role cannot use the team's cloud-managed distribution certificate, and
the export step is where that shows up. `APPLE-SETUP.md` in the repository
root walks through producing all four.
